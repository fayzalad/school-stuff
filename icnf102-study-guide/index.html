01Communication & the Rules

Before any protocol, three things must exist and a set of rules must govern them. Nearly every "why" answer later in the course traces back to one of the rules below.

The three elements of every communication

  • Source (sender) — the device that originates the message.
  • Destination (receiver) — the device that interprets it.
  • Channel (media) — the path the message travels along.

Rules — protocols — govern all methods of communication, human or machine.

What protocols must define

General communication requires an identified sender and receiver, a common language and grammar, agreed speed and timing of delivery, and confirmation or acknowledgement requirements. Network protocols additionally define five things you should be able to list from memory:

The five network communication rules
RuleWhat it governs
Message encodingConverting information into an acceptable form for transmission; decoding reverses it. Bits become patterns of light, sound or electrical impulses.
Message formatting & encapsulationThe structure a message must use. Format depends on message type and the channel delivering it.
Message sizeEncoding must suit the medium; long messages are broken into pieces that fit.
Message timingFlow control, response timeout, access method — see below.
Message delivery optionsUnicast, multicast, broadcast (and anycast in IPv6).

Message timing, broken down

  • Flow control — manages the rate of transmission: how much can be sent and how fast.
  • Response timeout — how long a device waits when it hears no reply from the destination.
  • Access method — determines when a device may send. This is where collisions arise: two devices transmit at once and both messages corrupt. Some protocols are proactive (try to prevent collisions); others are reactive (recover after one).

Delivery options

Unicast

One to one. A single source to a single destination.

Multicast

One to many — a defined group, typically not everyone.

Broadcast

One to all on the local network.

Classic trap

Broadcast is used in IPv4 but is not an option in IPv6. IPv6 replaces its uses with multicast and adds anycast — one address assigned to multiple devices, reached at whichever is nearest.

02Reference Models & Encapsulation

Two layered models, one encapsulation process, and the PDU names that go with it. Expect to be asked which layer a protocol lives at, and what the data is called at that point.

Why layer at all

  • Assists protocol design — each layer has defined information to act on and defined interfaces above and below.
  • Fosters competition — products from different vendors interoperate.
  • Isolates change — a technology change in one layer doesn't affect the others.
  • Provides a common language for describing networking functions.

The comparison, in one line

OSI splits TCP/IP's Network Access layer into Data Link + Physical, and its Application layer into Application + Presentation + Session. The TCP/IP suite does not specify which protocols to use when transmitting over a physical medium — that is why OSI layers 1–2 are needed to describe media access.

Protocol suites

A protocol suite is a group of inter-related protocols necessary to perform a communication function. The main ones:

  • TCP/IP (Internet Protocol Suite) — most common; maintained by the IETF. It is an open standard (freely available, usable by any vendor) and standards-based (endorsed by the industry, approved by a standards organisation to ensure interoperability).
  • OSI protocols — developed by ISO and ITU.
  • AppleTalk — proprietary, Apple Inc.
  • Novell NetWare — proprietary, Novell Inc.

How four protocols cooperate to load one web page

EthernetNetwork AccessDelivers messages from one NIC to another NIC on the same Ethernet LAN.

Segmenting, sequencing, encapsulating

  • Segmenting — breaking messages into smaller units. Two benefits: increases speed (large data can cross the network without tying up the link) and increases efficiency (only failed segments are retransmitted, not the whole stream).
  • Multiplexing — interleaving multiple streams of segmented data together.
  • Sequencing — numbering segments so the message can be reassembled at the destination. TCP does this.
  • Encapsulation — each protocol adds its own header information as data moves down the stack.

Encapsulation, web server to client

  1. Server prepares the HTML page; HTTP hands the data to the transport layer.
  2. Transport layer breaks the data into segments and identifies each one.
  3. IP source and destination addresses are added, creating an IP packet.
  4. Ethernet information is added, creating the Ethernet (data link) frame.
  5. The frame is delivered to the nearest router; each router adds new data link information before forwarding.

De-encapsulation at the client removes headers in the opposite order: Ethernet header, then IP header, then transport header, then HTTP data goes to the browser.

Addressing at two layers

Network layer (IP)

Delivers the packet from the original source to the final destination. Does not change end to end (NAT excepted). Split into a network portion (left-most bits) and a host portion.

Data link layer (MAC)

Delivers the frame from one NIC to another NIC on the same network. Re-written at every router hop.

Exam focus — same network vs remote

Same network: destination MAC = the MAC of the destination device.

Remote network: destination MAC = the MAC of the default gateway (nearest router interface). The router strips the Layer 2 information and adds new data link information before forwarding out the exit interface. The IP addresses never change.

03Physical Layer & Media

Layer 1 accepts a complete frame from the data link layer and encodes it as signals on the local media. Three media forms, three copper impairments, and a bandwidth/throughput/goodput distinction that gets asked almost every year.

What the physical layer does

  • Transports the bits that make up a data link frame across the network media.
  • Accepts a complete frame from the data link layer and encodes it as a series of signals transmitted onto the local media.
  • Encoded bits are received by either an end device or an intermediate device.

Standards bodies for layer 1: ISO, TIA/EIA, ITU, ANSI, IEEE.

Three functions the standards define

  • Physical components — hardware, media, connectors.
  • Encoding — converting a stream of data bits into a predefined "code".
  • Signalling — how bits are represented: what signal means 1 and what means 0. A long pulse might be 1, a short pulse 0.

Bandwidth, throughput, goodput

Three measures that are not the same thing
TermDefinition
BandwidthThe capacity of a medium to carry data — how much data can flow in a given time. Not speed: in both 10 Mb/s and 100 Mb/s Ethernet the bits travel at the speed of electricity; what differs is the number of bits transmitted per second.
ThroughputThe measured transfer of bits across the media over a given period. Usually lower than the stated bandwidth because of the amount of traffic, the type of traffic, and latency added by devices between source and destination.
GoodputThroughput minus traffic overhead for establishing sessions, acknowledgements and encapsulation. The useful data rate.

Copper media

Data is transmitted on copper as electrical pulses. Three impairments, and the countermeasure for each:

Copper impairments
ImpairmentWhat it isCountermeasure
AttenuationThe longer the signal travels, the more it deteriorates.Strict distance limitations on all copper media.
EMI / RFIElectromagnetic or radio frequency interference distorts and corrupts the signal.Shielding the cable.
CrosstalkDisturbance caused by the electric or magnetic field of a signal on one wire affecting an adjacent wire.Twisting opposing circuit wire pairs together.

Coaxial cable

Copper conductor → flexible plastic insulation → woven copper braid or metallic foil (second wire in the circuit and a shield) → outer cable jacket. UTP has essentially replaced coax in modern Ethernet, but coax survives in wireless installations (attaching antennas) and cable internet.

UTP vs STP

UTP — Unshielded Twisted Pair

The most common networking media. Four pairs of colour-coded wires twisted together. Terminated with RJ-45. No shielding — relies entirely on cancellation: two wires placed close together have exactly opposite magnetic fields which cancel outside EMI/RFI. The number of twists per pair is varied to enhance the cancellation effect.

STP — Shielded Twisted Pair

Better noise protection, significantly more expensive and harder to install. Also uses RJ-45. Combines shielding (against EMI/RFI) with twisting (against crosstalk). Four pairs, each in a foil shield, all wrapped in an overall metallic braid or foil.

Fibre-optic cabling

Bits are encoded as light pulses. Transmits over longer distances at higher bandwidths, with less attenuation, and is completely immune to EMI and RFI. A flexible but extremely thin strand of very pure glass, not much bigger than a human hair.

Four industries: enterprise networks, Fibre-to-the-Home (FTTH), long-haul networks, submarine cable networks.

Remember

Light travels in one direction only over optical fibre, so two fibres are required to support full-duplex operation. Patch cord jacket colours: yellow = single-mode, orange (or aqua) = multimode.

Connectors: ST (straight-tip, one of the first, twist-on/twist-off lock), SC (subscriber / square / standard, push-pull, used with both multimode and single-mode), LC simplex (a smaller SC, popular for its size), and duplex multimode LC.

Field-test by shining a bright flashlight into one end; use an OTDR (Optical Time Domain Reflectometer) to test each segment properly.

Wireless media

Carries electromagnetic signals representing the binary digits, using radio or microwave frequencies. Four areas of concern:

  • Coverage area — building construction materials and local terrain limit coverage.
  • Interference — disrupted by fluorescent lights, microwave ovens and other wireless communications.
  • Security — unauthorised devices and users can gain access to the transmission.
  • Shared medium — only one device can send or receive at a time; the medium is shared among all wireless users.

04Data Link Layer & Ethernet

Layer 2 prepares network data for the physical network. Two sublayers, two duplex modes, two access methods, one frame you must know field by field.

The two sublayers

LLC — Logical Link Control

The upper sublayer. Communicates with the network layer. Identifies which network layer protocol is being used for the frame, allowing multiple Layer 3 protocols (IPv4 and IPv6) to use the same interface and media.

MAC — Media Access Control

The lower sublayer. Defines the media access processes performed by the hardware. Provides data link addressing and access to network technologies; communicates with Ethernet (copper/fibre) and with wireless technologies like Wi-Fi and Bluetooth.

The MAC sublayer's two responsibilities

  • Data encapsulation — three functions: frame delimiting, addressing, error detection.
  • Media access control — controls frame placement on and off the media (like traffic rules on a road) and handles media recovery.

Duplex

Half vs full duplex
ModeBehaviourWhere you see it
Half-duplexBoth devices can transmit and receive, but not simultaneously.Legacy topologies, Ethernet hubs, and all WLANs.
Full-duplexBoth devices can transmit and receive at the same time. The data link layer assumes the media is available to both nodes at any time.Ethernet switches — full-duplex by default, but will drop to half-duplex when connecting to a hub.
Classic trap

Duplex mismatch — one port at half-duplex while the other is full-duplex — is a common cause of Ethernet performance problems. Most devices avoid it using autonegotiation, which exchanges speed and duplex capabilities and picks the highest performance mode.

Media access control methods

Three access methods
MethodHow it works
Controlled accessEach node has its own turn to use the medium. Legacy Token Ring LANs are the example.
CSMA/CDCollision Detection — used in half-duplex Ethernet LANs. If two devices transmit at once a collision occurs; both detect it, both sets of data are corrupted and must be resent. Comes into effect after the collision.
CSMA/CACollision Avoidance — used in 802.11 wireless. Detects whether the media is clear and waits before transmitting. Does not detect collisions; tries to avoid them. Comes into effect before the collision.
Why switches changed everything

Ethernet LANs using switches do not use a contention-based system, because the switch port and the host NIC both operate in full-duplex. No contention means no collisions, which means CSMA/CD is not needed.

Ethernet

  • The most widely used LAN technology; defined in IEEE 802.2 (LLC) and 802.3 (MAC/physical).
  • Operates at the data link and physical layers.
  • Supports 10 Mb/s, 100 Mb/s, 1000 Mb/s (1 Gb/s), 10 Gb/s, 40 Gb/s and 100 Gb/s.

Frame size limits — memorise these numbers

If a transmitted frame is smaller than the minimum or larger than the maximum, the receiving device drops it.

MAC addresses

  • A 48-bit binary value expressed as 12 hexadecimal digits — 4 bits per hex digit. Example: 00:1B:44:11:3A:B7.
  • Hexadecimal is base-16, using 0–9 and A–F. Usually written with a 0x prefix in text (e.g. 0x73). Used for MAC addresses and IPv6 addresses.
  • Rules are established by the IEEE, which assigns each vendor a 3-byte (24-bit) OUI — Organizationally Unique Identifier.
MAC = 00:1B:44 : 11:3A:B7 → OUI (24 bits, IEEE-assigned) + vendor-assigned unique value (24 bits)

The two IEEE rules for vendors: every MAC assigned to a device must use that vendor's OUI as the first 3 bytes, and all MACs with the same OUI must have a unique value in the last 3 bytes.

The MAC address is often called the burned-in address (BIA) because it is encoded permanently into the ROM chip. At startup the NIC copies the MAC address from ROM into RAM.

Viewing it: ipconfig /all on Windows; ifconfig on macOS or Linux.

05LAN Switching

A Layer 2 switch makes forwarding decisions using only the Layer 2 MAC addresses. How it learns them, how it forwards, and the three forwarding methods.

The MAC address table

Also called the CAM table (content addressable memory). A switch that has just powered on has an empty table — it has not learned anything yet.

Learning — always from the SOURCE address

  1. The switch examines all incoming frames for new source MAC address information.
  2. If the source MAC is unknown, it is added to the table along with the port number it arrived on.
  3. If the source MAC already exists, the switch updates the refresh timer for that entry.

By default most Ethernet switches keep an entry for 5 minutes.

Forwarding — always using the DESTINATION address

Forwarding decision logic
Destination MAC is…Switch action
Broadcast or multicastFlood out all ports except the incoming port.
Unicast, found in the tableForward out the one specified port.
Unicast, not in the table (unknown unicast)Flood out all ports except the incoming port.

Frame forwarding methods

Store-and-forward vs cut-through
MethodBehaviourTrade-off
Store-and-forwardReceives the entire frame and computes the CRC. If the CRC is valid it looks up the destination address and forwards out the correct port.Full error checking; highest latency.
Cut-through: fast-forwardBuffers just enough to read the destination MAC, then forwards immediately. No error checking.Lowest latency — the most typical form of cut-through.
Cut-through: fragment-freeStores the first 64 bytes before forwarding.A compromise between store-and-forward and fast-forward — catches collision fragments.

Memory buffering

A switch may buffer frames before forwarding — also used when the destination port is busy due to congestion.

Port-based memory

Frames are stored in queues linked to specific incoming and outgoing ports. A frame is transmitted only once all frames ahead of it have been transmitted.

Shared memory

All frames go into a common buffer shared by all ports on the switch.

Auto-MDIX

Connections between specific device types — switch-to-switch, switch-to-router, switch-to-host, router-to-host — once required a specific crossover or straight-through cable. Auto-MDIX (automatic medium-dependent interface crossover) lets the switch detect the cable type and configure the interface accordingly. Enabled by default since IOS 12.2(18)SE; the command is mdix auto in interface configuration mode.

06Network Layer & the IP Packet

Four operations, three characteristics of IP, two packet headers, and how a host decides whether a destination is local or remote.

Four basic operations of the network layer

  1. Addressing end devices
  2. Encapsulation
  3. Routing
  4. De-encapsulation

IP encapsulates the transport layer segment. The packet is examined by all Layer 3 devices as it traverses the network, and the IP addressing does not change from source to destination — except where NAT is involved.

The three characteristics of IP

IP is deliberately low-overhead
CharacteristicWhat it means
ConnectionlessIP does not establish a connection before sending. No synchronisations or acknowledgements. The destination receives the packet when it arrives, with no prior notification. If connection-oriented behaviour is needed, another protocol handles it — typically TCP.
Best effortIP does not guarantee delivery. Reduced overhead because there is no mechanism to resend lost data. It expects no acknowledgements and does not know whether the other device is even operational.
Media independentIP does not concern itself with the frame type at the data link layer or the media type at the physical layer. It can be sent over copper, fibre or wireless.
IP is unreliable — and that is by design

IP cannot manage or fix undelivered or corrupt packets, cannot retransmit after an error, and cannot realign out-of-sequence packets. It must rely on other protocols for these functions.

MTU and fragmentation

  • The network layer establishes the MTU (Maximum Transmission Unit), using control information received from the data link layer.
  • Fragmentation is when Layer 3 splits an IPv4 packet into smaller units — for example when a router goes from Ethernet to a slow WAN with a smaller MTU. Fragmenting causes latency.
  • IPv6 does not fragment packets. Routers never fragment IPv6.

The IPv4 header

The IPv6 header

Three limitations of IPv4 that IPv6 exists to solve:

  1. IPv4 address depletion — we have essentially run out.
  2. Lack of end-to-end connectivity — private addressing and NAT extended IPv4's life but ended direct communication with public addressing.
  3. Increased network complexity — NAT was a temporary fix; manipulating header addressing causes latency and troubleshooting difficulty.

Three IPv6 improvements: increased address space (128 bits, not 32), improved packet handling (simplified header with fewer fields), and eliminating the need for NAT.

Classic trap

The IPv6 header is simplified but not smaller — it is fixed at 40 bytes. Three IPv4 fields were removed to improve performance: Flags, Fragment Offset and Header Checksum.

How a host routes

Packets are always created at the source, and every host device creates its own routing table. A host can send packets to three places:

  • Itself — 127.0.0.1 (IPv4) or ::1 (IPv6).
  • Local hosts — on the same LAN.
  • Remote hosts — not on the same LAN.
How the source determines local vs remote
ProtocolMethod
IPv4Uses its own IP address and subnet mask, plus the destination IP address.
IPv6Uses the network address and prefix advertised by the local router.

Local traffic is dumped out the host interface for an intermediary device to handle. Remote traffic is forwarded to the default gateway.

The default gateway

  • A router or Layer 3 switch can be a default gateway.
  • It must have an IP address in the same range as the rest of the LAN.
  • It can accept data from the LAN and forward traffic off the LAN, and can route to other networks.
  • No default gateway, or a bad one → traffic cannot leave the LAN.
  • A host learns it statically or via DHCP in IPv4; IPv6 sends it through a Router Solicitation / Advertisement, or it is configured manually.
  • A default gateway is a static route that acts as the route of last resort.

Host routing table commands (Windows): route print or netstat -r. Both display three sections: Interface List (interfaces and MAC addressing), IPv4 Routing Table, IPv6 Routing Table.

07Address Resolution — ARP & ND

A device knows an IP address and needs the MAC address that goes with it. IPv4 uses ARP; IPv6 does not use ARP at all.

The two addresses on every Ethernet host

  • Layer 2 physical address (MAC) — used for NIC-to-NIC communication on the same Ethernet network.
  • Layer 3 logical address (IP) — used to send the packet from source device to destination device, end to end.
Exam focus — the one rule to never get wrong

Destination IP on the same network → destination MAC is that of the destination device.

Destination IP on a remote network → destination MAC is that of the default gateway (the router interface).

ARP — Address Resolution Protocol (IPv4)

A device uses ARP to determine the destination MAC address of a local device when it knows its IPv4 address. Two functions:

  1. Resolving IPv4 addresses to MAC addresses.
  2. Maintaining an ARP table of IPv4-to-MAC mappings.

The ARP decision process

  1. To send a frame, the device searches its ARP table.
  2. If the destination IPv4 is on the same network, it looks up the destination IPv4 address.
  3. If the destination IPv4 is on a different network, it looks up the IPv4 address of the default gateway.
  4. If found, the corresponding MAC becomes the destination MAC in the frame.
  5. If no entry exists, the device sends an ARP request — a broadcast. The owner replies with an ARP reply, and the device adds the IPv4/MAC pair to its ARP table.

ARP table maintenance

  • Entries are not permanent — removed when the ARP cache timer expires. Duration differs by operating system.
  • Entries can also be removed manually by an administrator.

09IPv6 Addressing

128 bits written as eight hextets, two compression rules, three address types, and the SLAAC/DHCPv6 decision tree. Compression questions are almost guaranteed marks if you apply the rules mechanically.

Migration and coexistence — three techniques

Dual stack

Devices run both IPv4 and IPv6 protocol stacks simultaneously.

Tunnelling

The IPv6 packet is encapsulated inside an IPv4 packet.

Translation

NAT64 allows IPv6-enabled devices to communicate with IPv4 devices.

Representation — the two rules

An IPv6 address is 128 bits, written as eight 16-bit hextets of four hex digits each. The prefix length indicates the network portion and can range from 0 to 128; the typical prefix for most LANs is /64.

Rule 1 — omit leading zeros

Leading zeros in any 16-bit section may be omitted. This applies only to leading zeros — omitting trailing zeros would make the address ambiguous.

Before: 2001:0DB8:0001:5270:0127:00AB:CAFE:0E1F /64
After:  2001:DB8:1:5270:127:AB:CAFE:E1F /64

Rule 2 — the double colon

A double colon (::) can replace any single, contiguous string of one or more all-zero hextets. It may be used only once within an address — twice would produce more than one possible resulting address.

Preferred:  2001 : 0db8 : 0000 : 1111 : 0000 : 0000 : 0000 : 0200
Compressed: 2001:db8:0:1111::200
Exam focus — why the first zero group stayed

In the example above the 0000 in position 3 becomes 0 (rule 1), not ::, because :: is spent on the longer run of three zero hextets later in the address. Apply rule 1 everywhere, then spend :: once on the longest contiguous zero run.

Another worked example: 2001:db8:cafe:1:0:0:0:1 → 2001:db8:cafe:1::1.

SLAAC

Stateless Address Autoconfiguration lets hosts create their own unique GUA without a DHCPv6 server — useful because not every network has one, but every device needs a GUA. It is stateless: no server maintains address information about which addresses are in use and which are free.

The host acquires its 64-bit subnet information from the RA and must generate the remaining 64-bit interface ID itself, by one of two methods:

Randomly generated

The 64-bit interface ID is generated randomly by the client OS. This is the method Windows 10 uses, chosen for privacy.

EUI-64

Built from the host's 48-bit MAC address. Some OSs avoid it for privacy reasons, because it exposes the MAC address.

The EUI-64 process — three parts

  1. 24-bit OUI from the client MAC address, with the 7th bit — the Universally/Locally (U/L) bit — reversed.
  2. The inserted 16-bit value FFFE (hexadecimal) in the middle.
  3. 24-bit device identifier from the client MAC address.
MAC           FC:99:47 : 75:CE:E0
EUI-64 ID  FE99:47FF:FE75:CEE0   (FC → FE: the U/L bit flipped)

Duplicate Address Detection (DAD)

  1. The host sends an ICMPv6 Neighbor Solicitation with a specially constructed solicited-node multicast address containing the last 24 bits of its IPv6 address.
  2. If no device replies with a Neighbor Advertisement, the address is virtually guaranteed unique and can be used.
  3. If an NA is received, the address is not unique and the host must generate a new interface ID.

DAD is arguably unnecessary — a 64-bit interface ID gives 18 quintillion possibilities — but the IETF recommends it, so most operating systems perform DAD on all IPv6 unicast addresses regardless of how they were configured.

Key multicast addresses: ff02::1 = all-nodes, ff02::2 = all-routers.

The six-step method

  1. Write out your powers of 2 table.
  2. Write out your existing subnet mask in binary.
  3. Apply the formula 2ⁿ − 2 ≥ X, where X is the number of hosts required per subnet and n is the number of host bits needed for the answer to be ≥ X.
  4. Write out the new subnet mask, keeping only the required number of host bits (0s) and converting all unneeded 0s into network bits (1s).
  5. Note the octet containing the last network bit. That is the octet you increment in to find the next subnet.
  6. Calculate the broadcast address and usable host range for each subnet.
Why minus 2

Two addresses in every subnet are unusable by hosts: the network address (all host bits 0) and the broadcast address (all host bits 1). Hence 2ⁿ − 2 usable hosts. The number of subnets created, by contrast, is 2^(bits borrowed) with no subtraction.

Worked example A — 192.168.10.0/24, 50 hosts per subnet

Step 2 — existing mask. /24 means 24 network bits, leaving 8 host bits:

Step 3 — the formula. We need 50 hosts, so 2ⁿ − 2 ≥ 50. Try n = 5: 2⁵ − 2 = 30 ✗. Try n = 6: 2⁶ − 2 = 62 ✓. So we keep 6 host bits.

Step 4 — new mask. Convert the 2 unneeded host bits into network bits:

Step 5 — the increment. The last network bit is in the 4th octet, and that octet has 6 host bits → increment by 2⁶ = 64 in the 4th octet.

11VLSM

VLSM is simply taking one of your existing subnets and subnetting it further using the same technique. The discipline is the ordering: largest requirement first.

The rule

  1. List every subnet requirement and sort it largest to smallest by host count.
  2. Allocate the largest LAN from the start of the address space, using the smallest mask that fits it.
  3. Continue down the list, each subnet starting where the previous one's broadcast address ended.
  4. Put point-to-point WAN links last — they need exactly 2 usable addresses, so a /30.
Why largest first

Allocating a small subnet at the start of the block fragments the space and leaves no contiguous run big enough for the large LAN later. Sorting descending guarantees each block lands on a legal boundary for its own mask.

12Transport Layer

The link between the application layer and the lower layers responsible for network transmission. TCP versus UDP, port numbers, the three-way handshake, and how reliability and flow control actually work.

Responsibilities

  • Responsible for logical communications between applications running on different hosts.
  • Tracking individual conversations.
  • Segmenting data and reassembling segments; adding header information.
  • Identifying, separating and managing multiple conversations.
  • Uses segmentation and multiplexing to interleave different conversations on the same network.

IP does not specify how delivery takes place; transport layer protocols specify how to transfer messages between hosts and manage the reliability requirements of a conversation.

TCP server processes

  • Each application process running on a server is configured to use a port number.
  • A server cannot have two services assigned to the same port number within the same transport layer service.
  • An active application assigned to a port is considered open — the transport layer accepts and processes segments addressed to it.

The three-way handshake

  1. The initiating client requests a client-to-server communication session. (SYN)
  2. The server acknowledges the client-to-server session and requests a server-to-client session. (SYN, ACK)
  3. The initiating client acknowledges the server-to-client session. (ACK)

Its three functions

  1. Establishes that the destination device is present on the network.
  2. Verifies that the destination has an active service and is accepting requests on that destination port.
  3. Informs the destination that the source client intends to establish a session on that port.

Session termination — four steps

  1. The client has no more data to send and sends a segment with the FIN flag set.
  2. The server sends an ACK to acknowledge the FIN, terminating client-to-server.
  3. The server sends a FIN to terminate the server-to-client session.
  4. The client responds with an ACK to acknowledge the server's FIN.
Classic trap

Establishment is three steps; termination is four. Both directions must be closed independently, which is why there is no combined FIN-ACK-FIN shortcut.

The six control bit flags

Reliability and flow control

Guaranteed and ordered delivery

Segments may not arrive, or may arrive out of order. All data must be received and reassembled into the original order — sequence numbers in each header achieve this.

Data loss and retransmission

TCP retransmits segments for unacknowledged data. SACK (Selective Acknowledgment) is an optional feature negotiated during the three-way handshake: if both hosts support it, the receiver can explicitly acknowledge which segments were received, including discontinuous ones — so only the truly missing bytes are resent.

Window size and sliding windows

  • Flow control is the amount of data the destination can receive and process reliably. It maintains reliability by adjusting the rate of data flow between source and destination for a given session.
  • Sliding windows — the destination sends acknowledgements as it processes bytes received, and the source's send window is continually adjusted in response.

Maximum Segment Size

The MSS calculation — know the arithmetic

MSS is the maximum amount of data the destination device can receive. A common MSS with IPv4 is 1460 bytes.

A host determines it by subtracting the IP and TCP headers from the Ethernet MTU of 1500 bytes:

1500 (MTU) − 20 (IPv4 header) − 20 (TCP header) = 1460 bytes

Congestion avoidance

When congestion occurs, packets are discarded by the overloaded router. To avoid and control it, TCP employs several congestion handling mechanisms, timers and algorithms.

UDP communication

  • Low overhead — a small datagram header and no network management traffic.
  • Reassembly — UDP does not track sequence numbers and has no way to reorder datagrams. It reassembles data in the order received and forwards it to the application.
  • Server processes — assigned well-known or registered port numbers; UDP forwards the application data based on the port number.
  • Client processes — the client dynamically selects a port number from the private range as its source port; the destination is usually the well-known port of the server process. The same pair of ports is used in all datagrams of that transaction.

13Application Layer

The interface between applications and the network. The top three OSI layers, two network models, and the protocols that carry the web, email, names, addresses and files.

The upper three layers

The application, presentation and session layers of OSI together define the functions of the TCP/IP application layer. The application layer provides the interface between the applications used to communicate and the underlying network.

Presentation — three functions

1. Formatting (presenting) data at the source into a format the destination can receive. 2. Compressing data so the destination can decompress it. 3. Encrypting for transmission and decrypting on receipt.

Session — two functions

1. Creates and maintains dialogs between source and destination applications. 2. Handles the exchange of information to initiate dialogs, keep them active, and restart sessions that are disrupted or long idle.

For communication to succeed, the application layer protocols on source and destination must be compatible.

Two models

14DHCPv4

Four messages to get a lease, two to renew, and a router configuration you will be asked to reproduce from memory in the practical test.

Concepts

  • DHCPv4 assigns IPv4 addresses, subnet masks, gateways and other parameters dynamically. Since desktop clients make up the bulk of network nodes, it is an extremely useful time-saver.
  • A dedicated server is scalable and relatively easy to manage — but in a small branch or SOHO site a Cisco router can provide DHCPv4 without one. Cisco IOS includes an optional, full-featured DHCPv4 server.
  • The server leases an address from a pool for a limited period. Leases are typically 24 hours to a week or more. When a lease expires the client must ask for another address — though it is typically reassigned the same one.
  • The lease mechanism ensures clients that move or power off do not keep addresses they no longer need. On expiry the address returns to the pool for reallocation.

Obtaining a lease — four steps, DORA

  1. DHCPDISCOVER — the client broadcasts to identify any available DHCP servers.
  2. DHCPOFFER — a server replies offering a lease. If the client receives more than one offer (multiple servers on the network) it must choose one.
  3. DHCPREQUEST — the client identifies the explicit server and lease offer it is accepting.
  4. DHCPACK — the server acknowledges that the lease has been finalised.

If the offer is no longer valid, the server responds with a DHCPNAK (negative acknowledgment) and the process must begin again with a new DHCPDISCOVER.

Renewing a lease — two steps

  1. DHCPREQUEST — before the lease expires the client sends this directly (unicast) to the server that originally offered the address. If no DHCPACK arrives within a specified time, the client broadcasts another DHCPREQUEST so another server can extend the lease.
  2. DHCPACK — the server verifies the lease information and returns this.

Per RFC 2131, DHCPOFFER and DHCPACK can be sent as unicast or broadcast.

DHCPv6 equivalents

The DHCPv6 messages are SOLICIT, ADVERTISE, INFORMATION REQUEST and REPLY. And remember: DHCPv6 does not provide a default gateway — that comes only from the RA.

Configuring a Cisco IOS DHCPv4 server

  1. Exclude addresses. Exclude anything statically assigned — routers, servers, printers, management interfaces — to prevent duplicate-address errors. The command can be entered multiple times.
  2. Define a pool name with ip dhcp pool pool-name, which moves you into DHCP config mode (Router(dhcp-config)#).
  3. Configure the pool — at minimum the network and the default gateway.

15NAT

Three types, six terms, five advantages and five disadvantages, and the configuration for each type. NAT is configured at the border router.

What NAT is

  • A process to translate network IPv4 addresses — private to public.
  • Its purpose is to conserve public IPv4 addresses.
  • It is configured at the border router for translation.

The six NAT terms

The three types of NAT

Static, dynamic and PAT
TypeMappingKey points
Static NATOne-to-oneConfigured by the administrator and remains constant. Used for servers that must be reachable from outside at a predictable address.
Dynamic NATOne-to-one, from a poolUses a pool of public addresses assigned on a first-come, first-served basis. Requires enough public addresses for the total number of simultaneous sessions. A device cannot reach external networks if no addresses remain in the pool.
PAT (NAT overload)Many-to-oneMaps multiple private addresses to a single public address (or a few). Uses port numbers to forward response packets to the correct internal device, and validates that incoming packets were requested.

Advantages and disadvantages

Advantages

Conserves the legally registered addressing scheme · Increases the flexibility of connections to the public network · Provides consistency for internal addressing schemes · Provides network security

Disadvantages

Performance is degraded · End-to-end functionality is degraded · End-to-end IP traceability is lost · Tunnelling is more complicated · Initiating TCP connections can be disrupted

Configuration

Static NAT

! 1. Map the inside local address to the inside global (public) address
R1(config)# ip nat inside source static 172.16.16.1 64.100.50.1
! 2. Identify which interfaces are inside and which are outside

R1(config-if)# ip nat inside
R1(config)# interface s0/0/0
R1(config-if)# ip nat outside

Dynamic NAT

! 1. Define the pool of public addresses
R1(config)# ip nat pool NAT-POOL 209.165.200.226 209.165.200.240 netmask 255.255.255.224
! 2. Standard ACL permitting the addresses to be translated

! 3. Bind the ACL to the pool
R1(config)# ip nat inside source list 1 pool NAT-POOL
! 4. Identify inside and outside interfaces (as above)

PAT — two forms

! Form 1 — overload an address POOL: identical to dynamic NAT plus "overload"

! Form 2 — overload a SINGLE address, the exit interface's own
R1(config)# access-list 1 permit 192.168.0.0 0.0.255.255
R1(config)# ip nat inside source list 1 interface s0/0/0 overload
The one word that changes everything

Dynamic NAT and PAT-with-a-pool are the same four commands. The only difference is the keyword overload at the end of the ip nat inside source list statement. Without it, one inside host consumes one public address; with it, many share one.

16VLANs

A VLAN is a logical partition of a Layer 2 network. Segmentation, trunking, the four VLAN types, and the three inter-VLAN routing options.

Definition and behaviour

  • VLANs virtually segment LAN devices regardless of the physical location of the user or device — IT staff on the first, second and third floors can all be on one VLAN while HR and Sales are on others.
  • Multiple partitions can be created and multiple VLANs can co-exist. Virtual partitioning takes place inside a Layer 2 device, usually a switch.
  • Each VLAN is a broadcast domain, and one VLAN can span multiple physical LAN segments.
  • Hosts on the same VLAN are unaware of the VLAN's existence.
  • VLANs are mutually isolated — packets can pass between VLANs only via a Layer 3 device such as a router.

Configuring a VLAN and assigning access ports

Switch(config)# vlan 2
Switch(config-vlan)# name IT
Switch(config)# interface range Fa0/1 - Fa0/10
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 2

Trunks

  • A VLAN trunk is a point-to-point link that carries more than one VLAN.
  • Established between switches to support communication within VLANs that span switches.
  • Trunk ports are not associated with any VLAN.
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 99
Switch(config-if)# switchport trunk allowed vlan 10,20,30,99

Inter-VLAN routing

Layer 2 switches cannot forward traffic between VLANs without the assistance of a router. Inter-VLAN routing forwards traffic from one VLAN to another. Three options:

Legacy inter-VLAN routing

One physical router interface per VLAN. Doesn't scale — a router runs out of interfaces quickly.

Router-on-a-stick

One physical interface carries all VLANs over a trunk, divided into sub-interfaces — one per VLAN, each with its own IP address acting as that VLAN's default gateway.

Layer 3 switching with SVIs

The switch itself routes, using switched virtual interfaces. Fastest, no external router required.

The sub-interface address becomes the PCs' default gateway.

17Routing Concepts

Static versus dynamic, what a routing table entry actually contains, and the two tie-breakers: administrative distance and metric.

Static routing

  • Must be configured manually.
  • Must be adjusted manually by the administrator when the topology changes.
  • Good for small, non-redundant networks.
  • Often used alongside a dynamic routing protocol for configuring a default route.

Dynamic routing

Dynamic routes automatically:

  1. Discover remote networks
  2. Maintain up-to-date routing information
  3. Choose the best path to the destination
  4. Find new best paths when there is a topology change

Dynamic routing can also share static default routes with other routers. It is the best choice for large networks, and it helps the administrator by providing redundant paths and automatically implementing the alternate path when a link goes down.

Exam focus — three different tie-breakers, in order

1. Longest prefix match decides which route entry applies to a packet — the most matching far-left bits always wins, regardless of anything else.

2. Administrative distance decides which source's route gets installed when two protocols learn the same network. Lower AD wins — a static route (AD 1) beats RIP (AD 120).

3. Metric decides between two routes from the same protocol. Lower metric wins.

IPv6 routing tables

Displayed with show ipv6 route. An IPv6 routing table includes directly connected, static and dynamically learned routes, with the same field set: route source (C directly connected, L local, S static, R RIP, O OSPF, D EIGRP), administrative distance, metric, next hop and outgoing interface.

Designing a small network

Most businesses are small, so most business networks are small. A small network design is usually simple, typically with a single WAN connection provided by DSL, cable or Ethernet. Large networks need an IT department; small networks are managed by a local technician or a contracted professional.

Four device selection factors

  1. Cost
  2. Speed and types of ports/interfaces
  3. Expandability
  4. Operating system features and services

IP addressing: create a scheme and use it. All hosts and devices within an internetwork must have a unique address.

Applications, protocols and real-time traffic

Network applications

Applications that implement application layer protocols and can communicate directly with the lower layers of the protocol stack.

Application layer services

For applications that are not network-aware — programs that interface with the network and prepare the data for transfer.

Common protocols in a small network: Telnet and SSH for remote access (SSH being the secure choice); HTTP/HTTPS for web; SMTP to send mail with POP3 or IMAP to retrieve it; FTP and SFTP for file transfer; DHCP for IP configuration; DNS for name resolution. A single server can provide multiple services — it might be an email, FTP and SSH server at once.

  • Infrastructure — does it have the capacity and capability to support real-time applications?
  • VoIP — typically less expensive than IP telephony, but at the cost of quality and features.
  • IP telephony — employs dedicated servers for call control and signalling.
  • Real-time applications — the network must support QoS to minimise latency. RTP and RTCP are the two protocols that support real-time applications.

Network security

Three types of malware

Virus vs worm vs Trojan
TypeDistinguishing behaviour
VirusPropagates by inserting a copy of itself into another program, becoming part of it. Spreads from computer to computer, leaving infections as it travels.
WormReplicates functional copies of itself and causes the same kind of damage, but is standalone software — it does not require a host program or human help to propagate.
Trojan horseHarmful software that looks legitimate. Does not reproduce by infecting other files; must spread through user interaction — opening an email attachment, downloading and running a file.

Three categories of network attack

Attack taxonomy
CategoryDefinition
ReconnaissanceThe discovery and mapping of systems, services or vulnerabilities. Threat actors use internet tools such as nslookup and whois to determine the IP address space assigned to a corporation, then ping the publicly available addresses to find active ones.
AccessThe unauthorised manipulation of data, system access or user privileges. Exploits known vulnerabilities in authentication services, FTP services and web services.
Denial of serviceThe disabling or corruption of networks, systems or services.

The four access attacks

Access attack types
AttackHow it works
Password attacksImplemented using brute force, Trojan horse and packet sniffers.
Trust exploitationA threat actor uses unauthorised privileges to gain access to a system, possibly compromising the target.
Port redirectionA threat actor uses a compromised system as a base for attacks against other targets — e.g. using SSH (port 22) to reach compromised host A, which host B trusts, then Telnet (port 23) from A to B.
Man-in-the-middleThe threat actor is positioned between two legitimate entities to read or modify the data passing between them.

DoS and DDoS

DoS attacks are the most publicised form and among the most difficult to eliminate. They prevent authorised people from using a service by consuming system resources. They are relatively simple to conduct even by an unskilled threat actor, and interrupt communication causing significant loss of time and money.

A DDoS is similar but originates from multiple, coordinated sources. A threat actor builds a network of infected hosts called zombies; a network of zombies is a botnet; the actor uses a command and control (CnC) program to instruct the botnet to carry out the attack.

Mitigation

  • Defence in depth (a layered approach) — a combination of networking devices and services working in tandem. Devices and services include a VPN, ASA firewall, IPS, ESA/WSA and an AAA server.
  • Upgrade, update and patch — keep current with the latest antivirus versions. The most effective way to mitigate a worm attack is to download security updates from the OS vendor and patch all vulnerable systems. Make end systems download updates automatically.
  • AAA ("triple A") — the primary framework for access control on network devices. Authentication: who is permitted to access the network. Authorisation: what actions they may perform. Accounting: a record of what was done. Like a credit card — it identifies who can use it, how much they can spend, and keeps account of what was bought.

The six troubleshooting steps

  1. Identify the problem. Tools can be used, but a conversation with the user is often very helpful.
  2. Establish a theory of probable causes. This step often yields more than a few probable causes.
  3. Test the theory to determine cause. A technician may apply a quick fix to test; if that doesn't correct it, research further to establish the exact cause.
  4. Establish a plan of action and implement the solution.
  5. Verify the solution and implement preventive measures. Verify full functionality.
  6. Document findings, actions and outcomes. Very important for future reference.

Exam focus — the four decisions that carry the marks

1. version 2 and no auto-summary on all three routers. The design uses 172.16.10.0/24, 172.16.20.0/24 and 172.16.30.0/28 — different masks inside one classful network, so auto-summary would break it.

2. Advertise the loopbacks (192.168.10.0 and 192.168.20.0) but not the ISP link (200.0.0.0). The brief says so explicitly, and the default route is what reaches the internet instead.

3. The default route uses the exit interface (Gi0/0), not a next-hop address.

4. default-information originate is the only thing that gets that default route to B1 and B2. Without it the PCs cannot ping the ISP loopback 1.1.1.1 even though everything internal works.

Task 5 — testing

  1. show ip interface brief on each router — every used interface up/up.
  2. Ping the PC's own default gateway — proves the VLAN, the access port, the trunk and the sub-interface address all match.
  3. Ping across the serial link (10.0.0.1 ↔ 10.0.0.2) — proves the /30 addressing.

  5. show ip protocols — confirm version 2, auto-summary off, and the right networks advertised.
  6. Ping 1.1.1.1 from each PC. Failure here with everything else working points squarely at default-information originate.

Two that trip people up

ARP is usually placed at Layer 2 in this course even though it deals in IP addresses — it resolves to a MAC and is carried in an Ethernet frame. ICMP is Layer 3, not Layer 4, even though ping feels like an application.
